# Qynova ERP – Audit Report (Round 2)

| ID | Severity | File:Line | Problem | Fix |
|----|----------|-----------|---------|-----|
| A1 | High | `leaves/leaves.service.ts:322-323,441-442,519-520,619-620,656-657` | Role checks use lowercase `'admin'`, `'hr'` but DB stores `'Admin'`, `'HR'`. Every role comparison will silently fail for HR approvers, leaving all leave approvals open only to Admin (or no-one). | Use `.toLowerCase()` comparison or use `SYSTEM_ROLES` constants. |
| A2 | High | `auth/auth.service.ts:40-44` | Login checks `user.status !== 'active'` AFTER the password check. A disabled/relieved user whose password matches can pass the password step (failed attempts are NOT recorded for disabled users, but worse: the status check comes too late if `disabled` is not in the ENUM set). Also `users.status` ENUM is `active / inactive / disabled` but login only rejects when not `active` — correct, but the error message does not distinguish locked vs disabled vs relieved. | Add specific error for `disabled` (Account disabled, contact HR), keep lock message for `locked_until`. |
| A3 | High | `auth/auth.service.ts:104-146` | `refreshTokens()` checks `user.status !== 'active'` but does NOT check `lifecycle_stage === 'relieved'` on the employee record. A relieved employee whose user is still `active` can keep refreshing tokens indefinitely. | On refresh also check that no linked employee has `lifecycle_stage = 'relieved'`. Already partially fixed by `relieved` transition setting `users.status = 'disabled'` but that only fixes future transitions, not old data. |
| A4 | High | `leaves/leaves.service.ts:322-323` | `roles.includes('admin')` — lowercase mismatch means HR users cannot approve leaves (only Admin can, bypassing permission middleware). | Fix to `SYSTEM_ROLES.HR` / `SYSTEM_ROLES.ADMIN` with case-insensitive compare. |
| A5 | High | `employees/employees.service.ts:100-148` | `createEmployee` transaction is correct BUT `initial_salary` field is accepted in schema (line 61) and described in a TODO comment. The salary structure table referenced (`salary_structures`) does not exist and there is NO payroll module yet. Any call passing `initial_salary` is silently ignored. | Note this is acceptable per spec (Dev 2 payroll not built), add migration for `salary_structures` to support Phase 5. |
| A6 | High | `attendance/attendance.service.ts:310-315` | Monthly calendar sets future dates with `status: 'absent'` and code `'-'` which is inconsistent — future days should not be counted as absent yet. The `totalAbsent` counter also incorrectly increments for `dateStr <= todayStr` including today when not punched yet. | Future dates → `status: null`, code `'-'`. Today not punched yet → `status: 'absent'` only when `dateStr < todayStr`, not `<=`. |
| A7 | Medium | `leaves/leaves.service.ts:619-620` | `getTeamCalendar` checks `roles.includes('admin')` lowercase again — HR cannot view team calendar. | Fix casing. |
| A8 | Medium | `auth/auth.service.ts` | `changePassword` does NOT enforce the first-login password rules: min 8 chars, 1 uppercase, 1 lowercase, 1 digit, different from current. The frontend only checks 6 chars. | Add backend Zod validation for password strength; add check that `newPassword !== oldPassword` by comparing with `bcrypt`. |
| A9 | Medium | `employees/employees.repository.ts:41` | `findAll` filters `whereNull('e.deleted_at')` — correct. But the **daily sheet** and **monthly sheet** in attendance do NOT filter out `lifecycle_stage = 'relieved'` or `status = 'inactive'` employees. Relieved employees appear in the attendance grid. | Add `whereNot('lifecycle_stage', 'relieved')` filter to `getDailySheet` and `getMonthlySheet` DB queries. |
| A10 | Medium | `frontend/src/shared/navigation/menuConfig.ts:106,154` | Group titles contain `(Dev 2)` and `(Dev 3)` text visible to end users. `Clients`, `Projects`, `Tasks`, `Invoices` are shown in the menu even though they are not built and produce 404s. | Remove `(Dev 2)` and `(Dev 3)` text. Hide Dev 3 items entirely. |
| A11 | Medium | `frontend/LoginPage.tsx:119-170` | "Quick Test Credentials" buttons are shown in production (no `import.meta.env.DEV` check). | Wrap in `{import.meta.env.DEV && ...}` guard. |
| A12 | Medium | `frontend/LoginPage.tsx` | No password show/hide toggle. | Add eye icon toggle for password visibility. |
| A13 | Medium | `frontend/ChangePasswordPage.tsx:29` | Password minimum is 6 characters; spec requires 8 with complexity rules shown live. Missing: uppercase, lowercase, digit rule checks, "different from temp password" check, live strength indicator. | Add rules panel that checks in real time. |
| A14 | Medium | `frontend/AuthContext.tsx:70-72` | After login, redirect ignores any saved `location.state.from` path (the page the user tried to open before being sent to login). | Store `from` location in ProtectedRoute and redirect to it on successful login. |
| A15 | Low | `attendance/attendance.service.ts:523` | Monthly matrix sheet marks unrecorded days as absent if `dateStr <= todayStr`, which marks **today** absent during work hours. | Change to `dateStr < todayStr` (strict less-than). |
| A16 | Low | `shared/navigation/menuConfig.ts` | `Timesheets` and `Payroll` menu items point to `/timesheets` and `/payroll` which have no routes defined → will redirect to root on click. | Remove items for unbuilt modules or add placeholder 404 routes. |
| A17 | Low | `audit-logs` frontend page | Phase 2 spec says to remove Audit Logs from frontend menu and routes but keep backend. | Remove frontend route, page component import, and menu item. |
| A18 | Low | `leaves/leaves.repository.ts` | `syncAttendanceForLeave` writes attendance only on leave approval. But `revertAttendanceForLeave` on cancellation does not check if the attendance has subsequent manual edits, so it may overwrite legitimate admin corrections. | Add check: only revert if `edited_by IS NULL`. |
| A19 | Low | `employees/employees.service.ts` | `createEmployee` does not filter out `relieved` lifecycle from reporting manager dropdown lookups. Relieved managers appear selectable. | Add `whereNot('lifecycle_stage', 'relieved')` to manager validation query. |
| A20 | Low | `frontend/EmployeeCreatePage.tsx` | No salary section, no resume upload. Phase 2 spec requires both. | Add salary section (monthly_salary field → creates `salary_structures` row) and optional resume upload with `employee_documents`. |
